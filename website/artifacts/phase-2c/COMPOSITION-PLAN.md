# Phase 2C composition plan — before implementation

## Composition
The hero is an editorial launch composition: large ivory “Three applications. One greater possibility.” typography, restrained mint serif emphasis, three named product identities and a compact honest package status. A broad, sharp Studio interface anchors an asymmetric triptych; Nexus and Sentry form a second tier. Screens remain uncropped, at native ratios. No imagery is used as a cinematic backdrop. At mobile sizes the text and availability come first, followed by a readable Studio screen and two companion interfaces. The hero is not a download form.

Applications follow as three distinct, generously spaced identities with product links and explicit independent responsibilities. The imagery above supplies recognition while these rows clarify purpose. Mint/ivory, purple and green distinguish Studio, Nexus and Sentry without introducing separate websites.

The Living Workflow follows immediately. A full-viewport dark canvas carries six persistent semantic information nodes and SVG relationships through four acts. One native scroll clock drives geometry, camera, labels and progress. Four compact chapter buttons seek that same clock. No dashboard sidebar, floating document or raster scenery. A readable four-act narrative is always available and is the primary reduced-motion alternative.

1. **Imagine / Studio (0–.27):** capture → connected requirements → structured plan. Close serif thought opens outward into a structured knowledge map.
2. **Orchestrate / Nexus (.27–.50):** plan becomes dependency lanes; requirements become work scope and review package. Camera shifts laterally, accents become purple.
3. **Question / Sentry (.50–.73):** the same package aligns into an independent audit plane. Example findings and open questions become attached context. Green, ruled surfaces; no fake success counters or simulated live run.
4. **Evolve / Nexus → Studio (.73–1):** findings return to Nexus first (.73–.86), align with execution scope, decisions and outstanding work, then resolve into richer Studio knowledge (.86–1). No Sentry-to-Studio shortcut.

Downloads is a quiet release ledger after the demonstration, with a prominent escape link directly to it. Current unavailable metadata produces no OS/architecture form or invented version. Future verified artifacts alone populate native selectors and download links. Documentation explains the independent application boundary, and a concise hardware research teaser closes the page.

## Ownership and architecture review
1. Source of truth: a typed local distribution catalog owns release facts; one GSAP timeline owns film geometry; native scroll owns current progress.
2. Ownership: new suite-launch components and CSS module own only `/suite`; approved concept and Landing remain untouched.
3. Dependencies: server route → launch sections/release UI/film; film → pure timeline factory. No application repository dependency or runtime integration.
4. Boundaries: typed release artifacts, product IDs, act records and geometry points. No any-shaped metadata or derived download URLs.
5. Failure: empty catalog stays unavailable, no link. JS failure leaves static readable narrative and screenshot content. No execution occurs.
6. Lifecycle: GSAP matchMedia/context owns all timelines and triggers, reverted on unmount or media change. No global scroll interception or listeners without cleanup.
7. Test seams: catalog eligibility, visible metadata, native seek/progress agreement, persistent nodes, all return phases, reversal, mobile bounds, reduced motion and route navigation.
8. Compatibility/rollback: existing concept files and Landing hashed before edits. Old Suite components remain available, route changes are isolated. Update tests tied specifically to the replaced design; retain Landing/concept behavior tests.
9. Observability: scoped data attributes expose act, workspace, ready and normalized progress; browser errors and recording evidence accompany rendered review. No telemetry added.
10. Security: no user data, external fetch, executable input or application authority. Artifact URLs must be HTTPS and carry verification evidence; absent/withdrawn facts cannot enable downloads.
