# Issues found and corrected during Phase 5A

1. Desktop pointer selection initially hit the perspective plane rather than its painted child. Actual Chromium click logging showed the camera div as event target, while programmatic button activation worked. `first-motion-test.log` records the failing real-mouse regression. The camera is now pointer-inert and slots explicitly accept pointer events. The same test passes, including lift/expansion/recession/reverse transforms. Mobile/keyboard did not mask the pointer defect.
2. Inspection typography originally used large final styles at the beginning of flight. The motion layer now interpolates selected surface typography and padding from its source styles; the geometry and type grow together.
3. Tablet screenshot review found the authentic window protruding into the collection reader and obscuring too much of the revision notebook. The tablet arrangement is adjusted before final capture so all objects remain inside the desk, with only intentional corner overlaps. Phone spacing similarly keeps observation text clear.
4. Closing during expansion kills the active timeline and reverses from the current measured state. Resize/motion changes also finish an already closing transition immediately. Source button visibility and sibling transforms are always cleared and native body overflow restored on return/unmount.

No existing assertions are weakened and no existing test files changed. Baseline: 110 passed before implementation. The eleven new concept tests add independent object access, exact return bounds, real matrix changes, keyboard/touch-sized viewport access, focus containment/restoration, early close, resize recovery, local sample editing, download honesty and reduced motion.

5. Video review detected a visible desk scroll jump in locator-driven capture. Event tracing showed `scrollY` had already changed **before pointerdown**: Playwright's locator click re-centered a 3D-transformed element, rather than native dialog code moving the page. The real-pointer test now clicks the measured visible coordinates, keeping the same strict pre/open/return scroll assertion; touch gets its own native tap test. Recording uses raw mouse coordinates too. The modal also explicitly captures/restores the page position around show/close, so its focus lifecycle cannot relocate the desk. The anchor-settle check accounts for both the existing 90px HTML scroll-padding and this page's 100px scroll-margin; a temporary 100px-only wait was a test setup error, documented in diagnostic logs.
