
ARTHUR
PHASE 3 — LOCAL VOICE LAYER
DeepSeek V4 Flash + Local STT/TTS Implementation Specification
Version 1.0  •  August 2026
PURPOSE
Phase 3 gives ARTHUR a real local voice interface: wake word, voice activity detection, local speech-to-text, DeepSeek-backed reasoning, local text-to-speech, streaming playback, interruption/barge-in, push-to-talk fallback, and a deterministic voice state machine. Phase 3 does not implement phone/remote-node routing yet.


1. Phase 3 Goal
Extend the hardened Phase 1 Core and Phase 2 isolated memory/RAG system with a low-latency, hands-free local voice experience. The user should be able to say the wake word “Arthur”, speak naturally, have the utterance transcribed locally, receive an answer reasoned by DeepSeek V4 Flash using the existing ARTHUR context/tool/memory stack, and hear the result through local TTS.
Voice is an input/output transport for ARTHUR—not a second assistant. Typed and spoken requests must converge on the same ConversationService, permissions, memory isolation, tool system, approval system, and DeepSeek ModelGateway.
NORTH STAR
The voice path must never weaken Phase 1/2 guarantees. A spoken request is subject to the exact same mode, RAG isolation, tool permission, approval, secret-safety, and audit rules as a typed request.
2. Entry Gate / Assumptions
Phase 1 security/idempotency/tool boundaries remain green.
Phase 2 Personal/Business memory isolation and RAG remain green.
DeepSeek V4 Flash remains the primary reasoning provider behind ModelGateway.
ARTHUR currently runs on the local PC/laptop; distributed node selection is deferred.
Audio capture/playback is local. Raw microphone audio is never sent to DeepSeek.
The existing text API/CLI path remains supported and must not regress.
3. Non-Goals — Do Not Implement Yet
Phone client, remote voice streaming, PC/laptop discovery, node failover, or mesh networking.
AgencyOS, AI Hoster, Cost Intelligence, or unrelated ecosystem applications.
Voice cloning of a real person without explicit rights/consent.
Always-uploaded microphone audio or cloud STT/TTS by default.
Emotion inference, speaker identity biometrics, or surveillance-style ambient transcription.
Multi-user household voice profiles.
Continuous conversation recording or long-term raw audio archives.
Custom hardware microphone arrays or far-field beamforming.
Replacing DeepSeek with a local 27B model in this phase.

}

All real engine-specific code remains inside local provider adapters. Tests use deterministic FakeWake/FakeVAD/FakeSTT/FakeTTS providers.
8. Audio Format Contract
Normalize microphone input to one internal PCM format before VAD/STT.
Use mono PCM with configured sample rate and frame duration; provider adapters resample only at boundaries.
AudioFrame timestamps are monotonic and local.
No compressed audio is stored unless explicitly enabled for debugging.
Playback format conversion happens inside AudioPlayback/TTS adapter boundaries.
PcmFrame {
  sequence: number
  timestamp_ms: number
  sample_rate_hz: number
  channels: 1
  sample_format: "s16le" | configured internal format
  duration_ms: number
  data: bytes
}

10. Wake Word Behavior
Wake detection runs locally continuously only while voice mode is enabled.
Wake provider receives short audio frames but does not persist them.
Wake event begins a fresh utterance capture window.
Pre-roll ring buffer may retain a very short in-memory window so the first spoken syllable is not lost.
Pre-roll is memory-only and cleared after each utterance.
Wake false positives return to IDLE after a configurable no-speech timeout.
Push-to-talk/hotkey must work even if wake engine is unavailable.
11. VAD and End-of-Utterance
VAD is the authority for when the user starts/stops speaking. Avoid sending silence to STT indefinitely.
Parameter
Requirement
speech_start_threshold
Configurable probability/debounce
speech_end_threshold
Configurable probability/debounce
min_speech_ms
Reject tiny clicks/noise
end_silence_ms
Natural pause before finalizing utterance
max_utterance_ms
Hard bound; finalize/cancel safely
no_speech_timeout_ms
Wake without speech returns to IDLE
12. STT Requirements
STT runs locally and never requires DeepSeek/network access.
Support Bulgarian and English at minimum; automatic language detection is allowed but language hints should be configurable.
Expose partial transcripts when the engine supports them.
Only the final transcript creates a ConversationService user turn.
Partial transcripts may appear in UI but must not be written to long-term memory.
Empty/low-confidence/noise utterances are discarded or ask for repetition.
Normalize whitespace/punctuation conservatively; do not rewrite meaning.
Bound maximum utterance duration and transcript length.
13. TTS Requirements
TTS runs locally.
ARTHUR has a stable configured voice persona independent from DeepSeek.
TTS supports cancellation at any point.
Prefer streaming/chunked synthesis; if engine is sentence-based, synthesize sentence chunks incrementally.
Playback starts before the full assistant response has been generated when safe.
Do not speak Markdown syntax, code fences, long URLs, JSON, citations, IDs, or raw tool payloads unless explicitly requested.
Preserve numbers, dates, units and names intelligibly.
TTS failures must still leave display_text available.
14. Speech Formatter
Do not send display Markdown directly to TTS. Add a speech-specific formatting layer.
AssistantOutput {
  display_text: string
  speech_text: string
  ...
}

Remove Markdown/control syntax from speech.
Collapse tables into short spoken summaries.
Do not read URLs character-by-character by default.
For code-heavy answers, say that code is shown on screen unless the user asks to hear it.
Keep spoken replies concise by default; display output may be richer.
Never alter tool approval semantics in the spoken summary.
15. DeepSeek Streaming Integration
Extend ModelGateway with a streaming capability without creating a second DeepSeek-specific conversation stack.
interface StreamingModelProvider extends ModelProvider {
  generateStream(request: ModelRequest, signal: AbortSignal): AsyncIterable<ModelStreamEvent>
}

ModelStreamEvent =
  | { type: "text_delta"; text: string }
  | { type: "tool_call"; call: ProposedToolCall }
  | { type: "usage"; usage: TokenUsage }
  | { type: "done"; finish_reason: string }

Non-streaming providers remain supported.
DeepSeek-specific SSE/event parsing remains inside DeepSeekProvider.
Cancellation uses AbortSignal/central CancellationScope.
Partial text is not persisted as final assistant turn until the response reaches a valid terminal state.
Tool calls interrupt/hold speech until tool/approval semantics are known.
16. Speakable Chunking
Do not feed token-by-token output to TTS. Buffer into speakable units.
text deltas
  -> sentence/phrase buffer
  -> safe boundary detector
  -> SpeechFormatter
  -> TTS queue

Prefer sentence boundaries.
Allow bounded phrase fallback when a sentence is very long.
Do not speak a fragment that could be invalidated by a pending tool call or approval.
Never speak hidden/internal metadata.
Backpressure prevents unlimited queued TTS when model output is faster than playback.
17. Barge-In / Interruption
CRITICAL EXPERIENCE REQUIREMENT
If ARTHUR is speaking and the user starts talking, playback must stop quickly and the new utterance must take priority. This behavior is required for Phase 3 completion.
User speech while SPEAKING
   |
Barge-in detector
   |
CancellationScope.cancel(reason="barge_in")
   +--> stop audio playback
   +--> cancel TTS synthesis
   +--> abort DeepSeek stream
   +--> cancel cancellable read-only tools
   +--> mark interrupted assistant turn
   |
start new LISTENING/CAPTURING utterance

Do not automatically cancel irreversible/external actions already approved and committed; cancellation policy is tool-specific.
Queued unsent TTS chunks are discarded.
Interrupted partial assistant text may be stored with status=interrupted for audit, not as a normal completed answer.
New utterance must not accidentally append to the interrupted model stream.
Cancellation is idempotent.
18. Echo / Self-Trigger Protection
ARTHUR must not repeatedly wake or transcribe its own TTS output.
Wake detector may be paused or hardened while TTS is playing.
Barge-in still needs microphone monitoring during playback; use echo-suppression strategy or tighter VAD/wake gating.
AudioPlayback exposes playback-active state to VoiceTurnController.
If acoustic echo cancellation is unavailable, prefer headphones or conservative software gating for V1.
Add a regression test where synthesized “Arthur” does not recursively create new turns.
19. Tool Calls and Voice
Voice must reuse Phase 1 tool security exactly.
Read-only tool results may be summarized and spoken.
Approval-required actions must pause before execution and ask the user for explicit approval.
Voice approval is treated as a user input turn/action and must bind to the exact pending approval object.
Phrases such as “yes”, “do it”, or “approve” are accepted only when there is exactly one unambiguous pending approval in the active trusted session.
If multiple approvals are pending, ARTHUR asks which one; it must not guess.
High-risk/User-only policy from Phase 1 remains authoritative.
Never convert arbitrary TTS/STT text directly into an adapter call.
20. Voice Approval UX
ARTHUR: "The Harness is ready to start job X. This will create a new coding job. Approve?"
USER: "Yes."
STT -> approval intent
ApprovalService resolves exactly one pending approval
-> verifies session/mode/action hash/expiry
-> executes through secured ToolOrchestrator

FAIL CLOSED
If “yes” could refer to more than one pending action or the approval has expired/changed, ARTHUR must not execute anything.
21. Session and Mode Integration
VoiceSession references an existing ARTHUR session_id.
Active Personal/Business mode is read from the server-side session store.
Voice UI may expose a mode-switch command, but it invokes the same explicit Phase 1 mode-change operation.
Wake word alone does not select a mode.
The spoken confirmation after a mode switch should make the active mode obvious when useful.
Phase 2 memory retrieval remains same-domain and is unaffected by voice.

26. Local Engine Selection Rules
Phase 3 architecture is engine-agnostic. The implementation may choose practical local providers compatible with the current PC, but the following contracts are mandatory:
Component
First-provider requirements
Wake word
Offline, low CPU, configurable “Arthur”, continuous local use
VAD
Offline frame-level speech probability/transition output
STT
Offline/local, Bulgarian + English, cancellable, acceptable realtime factor
TTS
Offline/local, natural stable voice, cancellable, supports streaming or incremental chunks
Document the chosen implementations and model versions in `docs/architecture/phase3-decisions.md`. Do not couple core contracts to those engines.
27. Audio Privacy
Raw microphone frames stay in memory buffers only by default.
Raw audio is not inserted into Personal/Business RAG.
Raw audio is not sent to DeepSeek.
Raw audio is not emitted in logs/traces.
Final transcript is treated like normal user text and therefore passes Phase 1 secret sanitization and Phase 2 mode/memory policy.
Optional debug recording requires an explicit development-only flag and obvious warning; never enable by default.
Microphone active/listening/speaking state must be visible to the local UI.
28. Transcript Safety
Apply input length bounds before creating a turn.
Do not trust STT confidence as authorization.
Transcription errors cannot bypass approval requirements.
Approval by voice should use contextual confirmation for high-impact actions.
Secret sanitizer runs on final transcript before persistence/model payload according to Phase 1 policy.
Partial transcripts are not persisted as completed user turns.
29. Cancellation Architecture
CancellationScope per voice turn
  signal
  cancel(reason)
  register(resource)

resources:
  STT stream
  DeepSeek stream
  TTS synthesis
  audio playback
  cancellable read-only tools

Cancellation reason is recorded as safe metadata.
Cancellation does not roll back already committed irreversible external actions.
Every provider adapter must release native/process/audio resources on cancellation.
After cancellation, late events from the old generation are ignored using utterance/turn generation IDs.
30. Generation / Stale-Event Guards
Every active utterance/turn receives a monotonically newer generation/ID. Async callbacks must verify they still belong to the current generation before mutating state or playing audio.
if event.voiceGeneration != controller.currentGeneration:
    ignore event

Old STT final events cannot create a new turn after barge-in.
Old DeepSeek deltas cannot be queued into the new TTS response.
Old TTS audio cannot resume after interruption.
Old timeout callbacks cannot return a new active session to IDLE unexpectedly.

37. Required Tests — State Machine
IDLE → wake → listening → capturing → final STT → thinking → speaking → IDLE.
Wake with no speech returns to IDLE after timeout.
PTT works with wake disabled.
Illegal transitions fail closed.
Disable from every active state cancels resources and reaches DISABLED.
Fatal provider error reaches ERROR/recovery without hanging.
Stale callbacks from older generations are ignored.
38. Required Tests — STT/TTS
FakeSTT partials do not create turns; final event creates exactly one turn.
Empty STT result creates no turn.
Long transcript is bounded/rejected safely.
Bulgarian and English sample utterances are recognized in optional local-provider smoke tests.
TTS formatter removes Markdown/code syntax.
TTS queue preserves response order.
TTS cancellation releases queued chunks and playback.
TTS failure still returns display text.
39. Required Tests — Barge-In
User speech during TTS stops playback promptly.
DeepSeek stream receives cancellation.
Queued TTS chunks are discarded.
Old model deltas after cancellation are ignored.
Old TTS audio after cancellation is ignored.
New utterance creates a new generation and turn.
Cancelling twice is safe/idempotent.
Committed external tool action is not incorrectly rolled back.
40. Required Tests — Security / Phase 1+2 Regression
Spoken Business request cannot retrieve Personal memory.

Actual DeepSeek payload contains transcript + same-domain context only, no raw audio.
Voice cannot call unknown/raw tool executor.
Voice “yes” cannot approve multiple ambiguous actions.

Secret-like spoken transcript follows Phase 1 sanitization policy.
Prompt injection spoken aloud cannot bypass tool or memory policy.
