# N7C platform monitoring and fresh validation

Pre-implementation review, 2026-10-24, accepted N7B 0e349a9:

1. Truth: OS subscriptions report possible change; fresh native reads supply route facts. Runtime owner retains generation/selection and the one admission pool; CaptureStore remains the sole durable owner.
2. Ownership: Coordinator explicitly starts/stops one monitor; an owned worker holds OS registration resources. Callbacks own only a bounded signal, never runtime/store/Activity references.
3. Direction: platform registration -> atomic signal/bounded dispatch -> existing runtime/pool. Stable event/fence types have no storage/provider/UI imports. Existing runtime construction token still gates pool creation.
4. Boundary: native callbacks convey invalidation only, using registration identity and monotonic epoch. Raw OS rows/COM objects/JNI local refs never cross callbacks into coordinator work. Synthetic observation construction/admission is explicitly test/debug-only and cannot enter the production evidence path.
5. Failure: missing permission/failed subscription/cleanup/OS read/changed facts refuse. Incomplete registration never authorizes admission. Failed fresh reads clear prior eligibility; overflow/terminal state cannot be reset by late callbacks.
6. Lifecycle: initialization stays passive. Explicit registration owns one bounded worker; callbacks increment an irreversible atomic epoch and coalesce one dispatch notification. Shutdown closes signals before unregister/join, outside owner/pool locks. In-flight permits read the epoch fence and are cancelled/woken by dispatch. Native callback contexts outlive unregister completion; cancellation failure retains inert context rather than freeing referenced memory.
7. Seams: actual Windows registration and Android permission/refusal/acquisition tests remain distinct from deterministic callback/fresh-read injection. Injected facts retain synthetic provenance and production admission rejects them. Barriers/channels, not sleeps, establish ordering.
8. Compatibility: schema9 and frozen writer/Sync/journal/D4 unchanged. No crypto or production permission change. An isolated standalone Android debug qualification project may declare ACCESS_NETWORK_STATE; it must be absent from default project settings and have release variants disabled.
9. Observability: typed subscription/read/cleanup errors and bounded epoch/event-kind counters for qualification; no network names/addresses/private keys logged or exposed through frontend APIs.
10. Security: events revoke, never grant. Admission validates owner/revision, acquires fresh OS evidence outside locks, compares every selected fact and rechecks event epoch/revision/cancellation before reserving the existing pool. OS-selected source stays false for Android LinkProperties. Pre-connect checks do not eliminate socket/disclosure TOCTOU. N1/N7 and all production activation gates stay closed.

Plan: introduce shared coalesced signal/fence and Windows/Android registration adapters; integrate explicit monitor ownership into Coordinator; seal native observation provenance and replace cached-only production admission; preserve existing synthetic tests through named qualification-only seams; add callback/race/no-effect tests and isolated Android OS tests; run all requested gates sequentially; document section23; commit/push current feature branch.

## Implemented contract

`Coordinator` stays inside the existing `NativeRuntime` and owns the same admission Pool. Construction is passive. `start_monitor` explicitly installs one worker; repeated starts share it. `stop_monitor` detaches and revokes that registration before joining, so a new registration cannot reuse an old epoch. Shutdown permanently closes the coordinator and pool. Ordinary teardown joins/unregisters outside state/pool locks. A shutdown reentered by an executor waker on the monitor worker cannot join itself: revocation is synchronous, native unregister follows when that dispatch returns. No accepted late event can restore eligibility in either case.

Windows registers AF_UNSPEC `NotifyRouteChange2`, `NotifyIpInterfaceChange`, and `NotifyUnicastIpAddressChange` with InitialNotification, and subscribes `INetworkEvents` through the NLM connection point. All NLM network properties (including category) revoke the registration fence. The worker owns its MTA, three notification handles, stable boxed IP callback context and COM subscription. Callback bodies ignore OS-owned rows, increment the checked atomic epoch and use a capacity-one `try_send`; they acquire no coordinator/pool/store locks, perform no route reads/COM and invoke no executor. Cleanup closes the signal, Unadvises and cancels each handle on the owning worker. Cancellation failure returns a typed refusal, retains the inert raw context instead of freeing possibly referenced memory, and quarantines future Windows subscriptions. This exceptional safety leak is intentional; native cancellation-failure injection has not been executed.

Android owns `RouteMonitor` through a JNI global reference supplied by the existing Application bootstrap. It registers `registerDefaultNetworkCallback` for available/lost/capabilities/link-properties/blocked-status events, without Activity/WebView references. Java only calls the private invalidation JNI entry point. A bounded registry of at most16 weak signal references uses checked monotonically increasing, never-reused tokens, not raw native pointers. The native callback copies a weak reference under the registry mutex and signals after releasing it. Teardown closes the epoch and removes the token before calling Java unregister outside owner/registry locks. Late tokens cannot access a destroyed runtime. Java registration/unregister errors refuse; unexpected registration/cleanup errors quarantine future Java registrations. The native registry also quarantines future subscriptions after uncertain JNI registration/cleanup failures; MissingPermission does not quarantine. No permission is requested or granted by these APIs. Normal-permission revocation and native resource failure injection remain unexecuted platform scenarios.

The epoch changes for every relevant event even if the one queue slot is already occupied. A permit retains its exact registration/epoch fence and checks it before establish, pending registration and framed operations, so revocation is observable before deferred owner dispatch. Dispatch clears cached eligibility, advances the checked owner revision, cancels active permits and wakes outside locks. Duplicate/reordered notifications only revoke. Epoch overflow closes the signal; revision overflow closes the owner. A queued event for a retired registration is ignored and cannot revoke or restore a newer selection.

Production selection requires an active native watch and a sealed native observation. Production admission rejects synthetic provenance, confirms owner/revision/exact endpoint, reads native OS facts outside locks, validates all selected facts (network, interface, physical medium, link, source, prefixes, route, next hop, endpoint, profile and permission), then rechecks owner/event epochs, shutdown and cancellation before reserving from the same Pool. Timestamps/revisions come from owner clocks, never callers. Failed acquisition or contradictory facts clear only the matching old revision, preserving any newer selection. Admission-limit/cancel refusals after a successful refresh do not erase other valid concurrent reservations. Rolling attempt history is never refunded by invalidation. Permit/waker teardown runs after releasing the coordinator lock. Synthetic completion and cached-fact admission helpers are private and compiled only for tests or the forbidden-in-release Android qualification feature.

This remains a pre-connect check. An OS change can occur between the final read/check and actual connection/disclosure, and the platform can delay notification delivery. Future socket integration must validate connected local/remote endpoints and current network/profile/permission before disclosing private data. No socket, listener, dialer, real encrypted-stream adapter or native timer was introduced. Route observations and permits are not authentication or production VerifiedSession capabilities.

## Android evidence levels and isolation

The shipped manifest continues to omit ACCESS_NETWORK_STATE. MissingPermission is a positive test of refusal (level A), not positive route evidence. The standalone `gen/android/qualification-network` project is absent from Tauri's settings and uses only the dedicated `dev.kaloyan.arthur.identitytest` application id; all non-debug variants are disabled. `verify-network.ps1` verifies package ids before installation and checks release-task absence. Its manifest adds ACCESS_NETWORK_STATE only inside this explicitly selected test project. Reusing the feature-enabled x86_64 library requires running `verify-identity.ps1` first. No default/release permission inheritance is permitted.

Actual ConnectivityManager/NetworkCapabilities/LinkProperties acquisition is level B. Android parsing deliberately keeps `source_selected=false`; LinkProperties is not OS socket-source selection (level C). API36 grants neither API37 ACCESS_LOCAL_NETWORK approval nor an NSD picker endpoint (level D). Positive Candidate evaluation and live LAN remain pending even if level B succeeds. No dummy connection is used.

## API contracts consulted

- [NotifyRouteChange2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-notifyroutechange2), [NotifyIpInterfaceChange](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-notifyipinterfacechange), [NotifyUnicastIpAddressChange](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-notifyunicastipaddresschange): AF_UNSPEC covers IPv4/IPv6, initial callbacks can have null rows, rows remain OS-owned.
- [CancelMibChangeNotify2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-cancelmibchangenotify2): cancellation cannot run inside that registration's callback or while holding resources that callback needs. Our cancellation runs on the monitor worker; callbacks never need owner/pool locks.
- [INetworkEvents](https://learn.microsoft.com/en-us/windows/win32/api/netlistmgr/nn-netlistmgr-inetworkevents) and [NetworkPropertyChanged](https://learn.microsoft.com/en-us/windows/win32/api/netlistmgr/nf-netlistmgr-inetworkevents-networkpropertychanged): NLM property notifications are invalidation, not a cached private-profile authorization.
- [ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager): default-network callbacks require ACCESS_NETWORK_STATE, must be explicitly unregistered, and are a bounded UID resource. Available/capability/link-property callbacks are not connected-source proof.
- [Android local network permission](https://developer.android.com/privacy-and-security/local-network-permission): API37 permission/picker policy is a separate unresolved decision; API36 emulator evidence cannot approve it.

## Security review

Separate end-to-end self-review covered provenance, lock order, JNI/COM lifetime, notification coalescing, overflow, cancellation and TOCTOU. No external independent audit is claimed. **Blocker corrected:** accepted N7B cached/synthetic selection could call production admission without another OS read. The new `n7c_synthetic_selection_cannot_admit_via_production_path` failed on the old implementation (0PASS/1FAIL) and passes with provenance rejection and hardwired fresh acquisition. Deterministic fresh-read tests additionally replace each network/profile/permission/route/source fact and verify old eligibility is erased, with no cached fallback. Existing N7B fixtures now use explicitly named qualification-only helpers; expectations and security checks remain intact.

Review also removed the new permit's cancellation-error destruction from under the coordinator lock, moved final watcher cleanup out of poisoned-pool error short-circuits, serialized signal detachment with registration control, and ensured terminal/overflow dispatch still wakes waiters. These are implementation-review corrections, not claims of separately reproduced baseline bugs. **Important remaining qualification:** actual host profile/route/VPN transitions, native cancellation errors, normal-permission revocation, Activity destruction during callbacks, physical/ARM64/API37 and successful release packaging. No new SQLite owner, migration, crypto dependency version, frontend command or provider/knowledge side effect was introduced. N1/N2/N3/N7 and G4–G7 remain unapproved; N1_AUDIT_PENDING/N7PolicyPending/ClosedTrust remain enforced. E3B has not started.

Qualification outcomes and final artifact evidence are recorded in [readiness section23](m05-activation-readiness.md#23-mega-n7c--event-driven-monitoring-and-fresh-validation-2026-10-2425). Standalone version-code downgrade refusal and the retained-handle/closed-registration status correction are retained there. Synchronous OS calls are not forcibly preempted; freshness checks reject slow results after return. Retrying a closed retained monitor requires explicit stop/cleanup before registration. No source-selection or LAN approval is inferred from successful Android read-only acquisition.
